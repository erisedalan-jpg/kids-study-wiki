# 考点词表标准化 · 全科全省程序计划

> **For agentic workers:** REQUIRED SUB-SKILL: 各阶段用 superpowers:subagent-driven-development 逐任务执行；本文是**程序级计划**（分期 + 可复用 recipe），每期执行时按 recipe 展开为微任务。

**Goal:** 把考点词表标准化（保守归并纯变体）+ 深度下游一致性（索引/反链/内部链接/概念别名全对齐）推广到全部省×科，并把吉林-数学长尾做到极致。

**Architecture:** 工具按 `--province --subject` 泛化；canonical 映射**按学科**（跨省共享）；每省科走统一 recipe：建/复用映射 → 迁移 → 深一致性（exam_index + fix_wikilinks/fix_stale_links + 概念别名对齐 + compute_weight）→ 验证 weight 漂移。吉林 4 科优先，再北京/湖南。

**Tech Stack:** Python 3.12 + PyYAML、unittest、既有工具（exam_index / compute_weight / fix_wikilinks / fix_stale_links / gen_html / gen_exam_blueprint）。

**前序 spec/plan：** `docs/superpowers/specs/2026-05-26-考点命名规范与词表标准化-design.md`、`docs/superpowers/plans/2026-05-26-考点词表标准化.md`（吉林-数学 已完成核心 5 任务 + 分组回填）。

**规模实测（2026-05-27）：** 13 省×科组合各 400–780 碎片考点；吉林-数学长尾剩 417 未分组（409 freq-1）；存量失链如 `[[向量数量积]]`×6 等。

**多模型路由：** 工具代码（P0）走 subagent TDD；canonical/group/别名 策展（数学领域判断）由 Opus 主会话；迁移执行 + weight 漂移验证主会话带过 diff 关卡。

## 每省科统一 Recipe（P2/P3 每个组合执行此模板）

> `S`=学科、`P`=省份。canonical 映射按学科共享：首次做某学科时建 `canonical_考点_<S>.yaml`（从该学科**全省**真题 dump 策展，保证完整），之后同学科其他省直接复用。

1. **建/复用映射**（Opus）：若 `canonical_考点_<S>.yaml` 不存在，dump 该学科全省考点按名排序 → 按 `00-元/考点命名规则.md` 6 规则聚类，仅并纯变体、保留语义粒度，逐条确认。
2. **weight 基线快照**：`grep -rH "^weight:" <S>/ | sort > working/_weight_before_<S>.txt`
3. **迁移**（主会话，过 diff）：git 干净 → `normalize_kaodian_source.py --province P --subject S`（dry-run 过 diff）→ `--apply` → 提交。
4. **深一致性**：
   a. `exam_index.py --province P --subject S`（重建该省科 高频考点/题型×考点交叉表/试卷地图/缺口清单 + 反链回填）。
   b. **概念别名对齐**（Opus）：看 exam_index 输出的「缺口考点」（真题命中但无概念词条）。对其中**实为已有概念另写法**的，给对应概念词条 frontmatter `aliases` 补该 canonical 考点名（使反链解析、weight 计入）；确无对应概念的留作真缺口（backlog 建词条）。
   c. `fix_wikilinks.py --apply` + `fix_stale_links.py --apply`（规范化/修内部 [[考点]] 链接；renumber 类 stale 修复）。
   d. `compute_weight.py --subject S --apply` → weight 漂移对比（应小且可解释，全升或零；**大批跳变/下降则停查误并**）。
   e. 刷新消费者：`gen_html.py --apply`；数学额外 `gen_exam_blueprint.py --apply`。
5. **验证 + 提交**：考点碎片数大降；单测回归；frontmatter 仅考点行变（抽查）；分省科提交重算产物。

## Self-Review

**用户三项覆盖：**
- 项①「最大化优化（长尾也做）」→ P1.1 长尾全覆盖 + 各科 Recipe 第 1 步完整策展 ✅
- 项②「索引/词条引用/知识库同步」→ 深一致性（Recipe 第 4 步 a-e：索引重生成 + 概念别名对齐 + fix_wikilinks/fix_stale_links 内部链接 + compute_weight）✅
- 项③「其他科目/省份同类问题」→ 实测确认 13 组合普遍碎片；P2（吉林物化生）+ P3（北京/湖南）滚动 ✅
- 优先级「吉林4科优先再其他省」→ P1/P2 吉林，P3 其他省 ✅
- 一致性深度「全对齐」→ Recipe 第 4 步含概念别名对齐 + 内部链接修复 ✅

**占位扫描：** 无 TBD；Recipe 步骤含确切命令；canonical/别名 策展为 Opus 执行产出（给了规则 + dump 法 + 硬标准），非空泛。

**类型/命名一致性：** canonical 映射统一 `canonical_考点_<学科>.yaml`；脚本参数 `--province/--subject` 跨 P0/Recipe 一致；深一致性工具链（exam_index→别名对齐→fix_wikilinks/fix_stale_links→compute_weight→gen_*）顺序在 Recipe 与各 Task 一致；weight 漂移关卡（小/可解释否则停）全程统一。

**风险：**
- **概念别名对齐误加** → 错误反链：别名只补「确为同概念另写法」者，遵守 alias 红线，逐条确认。
- **大体量**（13 组合 × 数百考点策展）：分期分科，每科映射一次到位跨省复用；Opus 策展为主成本，可按需拆多会话。
- **跨省独有写法**：P3 复用映射时增量补，不重建。
- **blueprint 仅数学**：物化生题位脑图扩科列 backlog，不阻塞标准化主线。
