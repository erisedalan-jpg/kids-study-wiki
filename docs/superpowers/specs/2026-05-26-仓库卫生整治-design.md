# 仓库卫生整治 — 设计

> 日期：2026-05-26 ｜ 状态：已确认，待实现
> 背景：根目录散落一次性中间产物且**已被 git 跟踪**，Obsidian Git 每 30 分钟自动 `vault backup` 反复提交，污染历史与真相源。

## 目标

1. 把被跟踪的一次性中间产物移出 git 跟踪，归到已忽略目录
2. 加固 `.gitignore`，杜绝下次 vault backup 再吞进同类文件
3. 给出 `working/` 本地堆积的一次性清理清单（纯本地，不进 git）

非目标：不改任何词条内容、不动现有脚本逻辑、不重构 `working/` 用途。

## 现状（实测）

被 git 跟踪的根目录散落文件（`git ls-files` 确认）：

| 文件 | 性质 | 处理 |
|---|---|---|
| `_missing2.txt` | 一次性诊断（缺口列表） | 移出跟踪 → `working/` |
| `_missing_alias.txt` | 一次性诊断（缺 alias） | 移出跟踪 → `working/` |
| `_tmp_test.py` | 临时试验脚本 | 移出跟踪 → `working/` |
| `hs_gaps.txt` | 一次性诊断（高中缺口） | 移出跟踪 → `working/` |
| `eng_todo.json` | 英语待办（可能仍在用） | 移出跟踪 → `working/`（保留文件本体） |
| `eng_todo.txt` | 同上 | 移出跟踪 → `working/` |

`docs/superpowers/working/`：本地 457 文件 / 25MB，已正确 gitignore（仅 `.gitkeep` 被跟踪）。

## 设计

### 第 1 步：散落文件移出跟踪并归位

对上述 6 个文件执行 `git rm --cached <file>`（保留工作区文件），再用 `git mv` 或手动移动到 `docs/superpowers/working/`。
- `git rm --cached` 而非 `git rm`：保留本地文件内容，仅断开跟踪。
- 移到 `working/` 后即落入现有 `docs/superpowers/working/*` 忽略规则，不再被备份提交。

### 第 2 步：加固 .gitignore

在根目录段落补充模式（放在「编辑器临时」附近，注明用途）：

```gitignore
# 根目录一次性诊断/临时产物（防 vault backup 误吞）
/_*.txt
/_*.py
/_*.json
/*_todo.*
/_tmp_*
```

注意：模式带前导 `/` 锚定**仅根目录**，不影响子目录内同名文件（如学科目录下的脚本不受影响）。补充后验证 `00-元/scripts/` 下的 `_utils.py`、`_exam_utils.py` 等下划线脚本**不被误伤**（它们在子目录，根锚定 `/_*.py` 不匹配）。

### 第 3 步：working 本地清理清单

`working/` 是一次性修补的暂存区，本地堆积无害但难找当前修补。给出清理建议（**不写自动删除脚本，列清单让用户决定**）：
- 保留：`.py` 工具脚本、`.gitkeep`
- 候选清理：`.txt` / `.log` 输出快照、`__pycache__/`
- 方式：提供一条 `find` 列出候选 + 大小的命令，用户确认后手动删

## 验收标准

- `git ls-files` 在仓库根目录下不再列出任何 `_*` 文件或 `*_todo.*` 文件
- 手动 `touch _probe.txt` 后 `git status` 不显示该文件（被新规则忽略）
- `git status` 干净，6 个文件以「移出跟踪 + 新增忽略规则」形式体现在一次提交里
- `00-元/scripts/` 下原有下划线脚本仍被 git 跟踪（未被误伤）

## 风险

- **vault backup 竞态**：实现期间若 Obsidian Git 触发自动备份，可能产生中间提交。实现时一次性完成 `git rm --cached` + gitignore 改动 + 提交，缩小窗口。
- **eng_todo 仍在用**：用户已确认可移到 `working/`（文件本体保留），如后续需要可从 working 取回。
