# 考点名语义近义归并检测 设计（v1）

> 状态：设计已确认（2026-05-28），待写实施计划。
> 关联：[[project_kaodian_vocab_blueprint]]（canonical 词表/分组体系）、`00-元/scripts/COMMANDS.md`「考点标准化 recipe」。

## 1. 背景与目标

canonical 考点表（`canonical_考点_<科>.yaml`，仅 4 理科）已按「**只并纯写法变体，绝不并语义不同项**」归并过。剩余缺口是**语义近义但非纯变体**的规范名对——靠人工眼扫易漏、不可复跑。

本工具把这步从手工启发式升级为**可复跑的体检**：对每科 canonical 规范名集合做 pairwise 词法相似度扫描，产出

- **人读报告**（分档 + 富化），供主会话 + 用户复核；
- **可应用合并草案** `proposed_merges_<科>.yaml`，人工删减后并入 canonical，走现有标准化 recipe 落地。

**红线安全**：工具只写两份草稿文件，**绝不改 canonical / 词条 / 真题**。合并永远是人工复核草案后的独立动作。

**范围**：4 理科（数学 / 物理 / 化学 / 生物，即有 canonical 表的科）。语文 / 英语 / 文科不在本期。

## 2. 非目标（YAGNI）

- 不做嵌入语义相似度（规模仅几百短串、环境无后端、真正需嵌入的恰是该留人工的）。`name_similarity` 做成可插拔接口，嵌入层列 backlog。
- 不做词条整页去重（另一目标对象，本期不做）。
- 不自动写 canonical、不自动跑下游 recipe（人工闸门）。
- 不做跨省真题聚合（默认吉林卷富化即可；多省聚合列 backlog）。

## 3. 数据来源（复用现有符号）

| 来源 | 读取方式 |
|---|---|
| 规范名集合（去重目标） | `canonical_考点_<科>.yaml` 的 RHS（规范名）去重集 |
| 父主题映射 | `group_考点_<科>.yaml`，复用 `gen_exam_blueprint.load_group`；未列入归「其他」 |
| 真题富化（真题数/题位/年份跨度） | `gen_exam_blueprint.read_rows(真题/吉林-<科>)` → 行内考点经 canonical 归一到规范名 → `kaodian_aggregate.build_kaodian_map(atoms, group)` |
| 对立词组 | 新增 `00-元/scripts/contrast_terms.yaml` |

> 注：数学优先 `normalize_考点_数学.yaml`、其余用 `canonical_考点_<科>.yaml`，与 `gen_exam_blueprint.paths_for` 一致。

## 4. 架构与组件

新增 `00-元/scripts/dedup_kaodian.py`：纯函数 + 薄 CLI（延续工具箱风格、`sys.path.insert` + bare import + `setup_utf8`）。

| 函数 | 签名（约定） | 职责 |
|---|---|---|
| `load_canonical_names` | `(subject) -> set[str]` | 读 canonical/normalize yaml，返回去重后的规范名集合 |
| `load_parent_map` | `(subject) -> dict[str,str]` | 规范名 → 父主题（缺 → 「其他」） |
| `load_exam_stats` | `(subject) -> dict[str,dict]` | 规范名 → {真题数, 题位, 年份跨度}；复用 read_rows + build_kaodian_map |
| `load_contrast_groups` | `(subject) -> list[set[str]]` | 读 contrast_terms.yaml（通用 + 该科） |
| `name_similarity` | `(a, b) -> float` | **可插拔**词法打分 ∈[0,1]（见 §5） |
| `is_contrast_pair` | `(a, b, groups) -> bool` | 对立守卫（见 §5） |
| `find_candidates` | `(names, parent_map, score_fn, th_review, groups, cross_parent) -> list[Candidate]` | 分桶 all-pairs 打分收集 |
| `cluster` | `(high_edges) -> list[set[str]]` | 并查集聚簇 |
| `choose_target` | `(cluster, stats) -> str` | 簇内选规范名（见 §6） |
| `render_report` | `(clusters, review_pairs, contrast_pairs, stats, subject) -> str` | 出报告 md |
| `build_proposed_merges` | `(clusters, targets) -> dict[str,str]` | 出草案 `变体: 规范名` |
| `main` | CLI | 见 §8 |

`Candidate` 为轻量数据结构：`(a, b, score, parent, is_contrast)`（dataclass 或具名元组）。

## 5. 相似度算法

四信号合成，均 ∈[0,1]：

- `s_bi`：字符 bigram 集 Jaccard
- `s_jac`：字符集 Jaccard
- `s_contain`：去尾缀（`运算`/`问题`/`的`）后一名是另一名子串 → 0.95，否则 0
- `s_edit`：`1 - lev(a,b)/max(len(a),len(b))`

```
score = max( s_contain, 0.6*s_bi + 0.25*s_jac + 0.15*s_edit )
```

**父主题约束**：默认只比同父主题桶内的对（「其他」自成一桶），降噪；`--cross-parent` 才跨桶比较。

**对立守卫（红线编码，关键）**：`is_contrast_pair(a,b,groups)` —— 若存在某对立组内两词 t1≠t2 使 `a.replace(t1,t2)==b`，返回 True。命中即标 ⚠️ 勿并、**剔出草案**、仅入报告「对立项警示」区，无论 score 多高。

`contrast_terms.yaml` 首版种子（可增长）：

```yaml
通用: []          # 预留
数学:
  - [乘法, 除法]
  - [正弦, 余弦]   # 正弦定理/余弦定理
  - [正弦, 正切]
  - [平行, 垂直]   # 线面平行/线面垂直、线线平行/垂直
  - [交集, 并集, 补集]
  - [最大值, 最小值]
  - [充分, 必要]
  - [奇函数, 偶函数]
物理:
  - [串联, 并联]
  - [电场, 磁场]
  - [动能, 势能]
化学:
  - [氧化, 还原]
  - [吸热, 放热]
  - [酸, 碱]
  - [正极, 负极]
生物:
  - [有丝分裂, 减数分裂]
  - [显性, 隐性]
  - [自交, 杂交]
```

**分档**：
- 高置信 `score ≥ 0.85` 且非对立 → 进合并草案 + 报告「高置信合并簇」
- 待复核 `0.65 ≤ score < 0.85` 且非对立 → 仅报告「待复核对」
- 对立项（任意分）→ 仅报告「⚠️ 对立项警示」

阈值 CLI 可调，默认 `--th-high 0.85 --th-review 0.65`，数学首跑后校准。

## 6. 聚簇与目标选择

高置信非对立边并查集聚簇（A~B、B~C → {A,B,C}）。簇内选规范名目标 `choose_target`：

1. 真题数最多者；
2. 并列 → 名最短者；
3. 再并列 → 字典序首位。

报告显式标出选定目标 + 各成员真题数，供人工推翻。草案 `build_proposed_merges`：簇内非目标成员 `成员: 目标`。

## 7. 输出格式

### 报告 `索引/考点去重/<科>-YYYY-MM-DD.md`

frontmatter（`type: meta`）+ 摘要行（规范名数 / 高置信簇数 / 待复核对数 / 对立警示数）+ 三区：

```markdown
## 高置信合并簇（建议并入 canonical）
- **目标：交集运算**（真题 8 · 选择1/2）
  - 交集（真题 0） ← score 0.95
  - 集合的交集运算（真题 1） ← score 0.92
  父主题：集合

## 待复核对（人工判断是否同义）
- 方程求解 / 方程的解法  — score 0.71 · 父主题 其他

## ⚠️ 对立项警示（差对立词，勿并）
- 正弦定理 / 余弦定理 — 命中对立组 [正弦, 余弦]
- 复数乘法 / 复数除法 — 命中对立组 [乘法, 除法]
```

### 草案 `00-元/scripts/proposed_merges_<科>.yaml`

```yaml
# 自动生成的合并草案——人工删减后，将保留行 append 到 canonical_考点_<科>.yaml，
# 再跑标准化 recipe（normalize → exam_index → compute_weight → gen_exam_blueprint）。
# 仅含高置信非对立项。绝不含对立项。
交集: 交集运算
集合的交集运算: 交集运算
```

## 8. CLI

```
python 00-元/scripts/dedup_kaodian.py --subject 数学 [--th-high 0.85] [--th-review 0.65] [--cross-parent]
python 00-元/scripts/dedup_kaodian.py --all
```

默认产出报告 + 草案两份草稿文件（非破坏性，不触 canonical/词条）。无 `--apply`——落地是人工后续动作。`--all` 遍历 4 理科。stdout 打印摘要行。

## 9. 下游落地（人工，非本工具）

复核报告 → 删减 `proposed_merges_<科>.yaml` → 保留行 append 进 `canonical_考点_<科>.yaml` → 跑现有 recipe：`normalize_kaodian_source` → `exam_index` → `compute_weight` → `gen_exam_blueprint`。即 COMMANDS.md 既有「考点标准化 recipe」，本工具不重复造。

## 10. 测试（unittest，PYTHONIOENCODING=utf-8）

- 各信号单测：`s_bi/s_jac/s_contain/s_edit` 已知输入。
- `name_similarity`：`(交集, 交集运算)` 高分；`(集合, 数列)` 低分。
- `is_contrast_pair`：红线对全 True——`(复数乘法,复数除法)`、`(正弦定理,余弦定理)`、`(线面平行,线面垂直)`、`(交集运算,并集运算)`；同义对 False——`(交集,交集运算)`。
- `find_candidates`：尊重父主题分桶；`--cross-parent` 才跨桶。
- `cluster`：传递闭包聚簇正确。
- `choose_target`：选真题数最多；并列走名最短。
- `build_proposed_merges`：对立项绝不入草案。
- **安全冒烟（真实数学 canonical）**：跑全流程，断言红线对（复数乘除 / 正余弦定理 / 线面平行垂直）**绝不出现在草案**、且出现在对立警示区。
- `render_report` / 草案 yaml 格式快照。

## 11. 边界与错误

- 科无 canonical yaml → 报错退出（非 4 理科）。
- 规范名缺父主题 → 「其他」桶。
- 规范名缺真题统计 → 真题数计 0，仍参与比较与聚簇。
- 空名 / 重复名 → 安全跳过。
- `索引/考点去重/` 目录不存在 → 自动创建。
